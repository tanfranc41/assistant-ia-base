# Phase 2 – Go / No-Go Checklist

## Statut
- Checklist historique (Phase 2 démarrée, auth minimale implémentée et gelée)
- À conserver comme référence de gouvernance

## Checklist (tout doit être OUI)
- Objectifs du projet clairement définis
- Périmètre de la Phase 2 validé
- Cible d’architecture relue et comprise
- Principes de sécurité identifiés
- Stratégie de persistance des données identifiée
- Approche d’authentification identifiée
- Risques identifiés et acceptés
- Responsable de décision de gouvernance identifié

## Décision
- [ ] GO : la Phase 2 peut démarrer
- [ ] NO-GO : la Phase 2 reste bloquée

## Règle
- Si un élément est décoché → NO-GO
- Le travail backend ne peut démarrer qu’après une validation GO explicite
