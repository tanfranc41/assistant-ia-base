# I18N (internationalisation)

## Langues supportées
- Français (référence)
- Anglais
- Néerlandais
- Allemand

## Structure des traductions dans `frontend/index.html`
- Objet `translations` avec une entrée par langue (`en`, `fr`, `nl`, `de`).
- Chaque entrée contient : `langName`, `title`, `labels` (`language`, `username`, `status`), `actions.logout`, `notice`, `statuses` (`loggedOut`, `authenticated`), `users` (`guest`, `demo`).
- Le HTML lit ces clés pour mettre à jour le titre, les libellés, le bouton et les messages.

## Fonctionnement du sélecteur de langue
- Le `<select id="language-select">` liste les langues et affiche leurs `langName`.
- Au changement, `currentLang` est mis à jour puis `render()` relit les traductions et met à jour le DOM.
- Aucun stockage : la sélection est volatile et se perd au rechargement.

## Ce qui est simulé (démo uniquement)
- Mise à jour des textes uniquement côté frontend.
- État utilisateur et jeton d’authentification stockés en mémoire dans la page.

## Ce qui n’est pas encore implémenté
- Backend ou API pour charger les langues.
- Authentification réelle ou validation de jeton.
- Persistance du choix de langue.
- Auto-détection de la langue (navigateur, profil utilisateur).

## Règles pour les évolutions
- Conserver le français comme référence et aligner les clés sur la structure existante.
- Ajouter toute nouvelle langue ou clé à toutes les entrées de `translations`.
- Ne pas ajouter de logique backend ni de persistance tant que le projet reste en mode démo.
- Documenter toute nouvelle clé ou règle dans ce fichier et ses équivalents localisés.
